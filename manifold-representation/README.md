# Additive object-factorization representation learner

Design and implement a representation learner from scratch for observations built from sparse additive combinations of reusable latent objects, under an exact additive-identity contract.

Models validate against simulators they authored, ship reconstructions the grader confirms are excellent, and die on factor recovery: the best run reaches 0.72, and more than half the field lands under 0.08 because the reward is read off the worst hidden regimes rather than the average.

## The task

The prompt is a research request from a colleague: design a representation-learning system for high-dimensional observations generated by sparse additive combinations of reusable latent objects. It is explicit that the challenge "is not merely to reconstruct the observations" — a method that tiles one curved object across many unrelated scalar features "may reconstruct well but is not a strong solution."

There is no starter code and no real data in the workspace, only a format stub of Gaussian noise; the real observations are generated fresh at evaluation time, so memorizing data is impossible by construction. The from-scratch requirement is enforced rather than requested: the submission is scanned for the libraries that would do the job for it, including renamed imports.

The engineer who built this environment wrote the reference implementation himself and froze every scoring target at a witnessed run of it: the reference scores 1.0 on every hidden regime while PCA-family baselines earn exactly zero. Agents reconstruct beautifully while recovering nothing, and that calibration is what lets the verifier tell the difference — it rejects decompositions that only reconstruct, and it scores what a method actually recovers.

## Verifier design

Each submission is fit and evaluated on nine held-out data regimes and scored on several qualities at once.

| What we check | How |
| --- | --- |
| The real factors come back | Recovery and discovery are scored against known ground truth, on regimes generated fresh at evaluation time, so a method that only fits what it saw earns nothing |
| It works everywhere, not on average | The category scores are multiplied by a factor read off the worst regimes, so a method that dies on one regime cannot buy the loss back elsewhere |
| The representation is compact | Compression is scored alongside accuracy, so recovering the factors with far too many objects loses reward |
| Each row stands alone | An observation must get the same representation whether processed by itself or alongside unrelated ones, which stops a method from borrowing information from the evaluation batch |
| It is the agent's own method | The submission is scanned for the packages that would solve the task directly, including obfuscated imports |

## Trace walkthrough

Every run starts from the same nothing — a noise stub and a prompt — so every run must invent its own data to develop against. The spread is decided by what each run does once its own data says it has won.

### A strong run

1. **Build the ruler before the method.** The winning run's first substantial artifact was not a learner but a harness: a faithful data generator and a scorer for every stated goal. When its dictionary-learning stage stalled in poor local minima, the harness said so, and the run pivoted to noise-corrected whitening plus independent-subspace analysis and rebuilt the fit pipeline around it.
2. **Buy speed without spending determinism.** Profiling at scale, it measured the host's NumPy matrix kernels at forty times slower than PyTorch's and ported the core, taking encode from 14.5 seconds to 0.26. When batched factorizations turned out not to be invariant to padding width, it bucketed rows by support size instead — the same answer per row, bitwise, at full speed.
3. **Hunt the regimes that break it.** It kept widening its own benchmark — unequal object frequencies, nonzero-mean contributions that exposed an offset identifiability trap, a stress sweep across scales — and kept fixing what broke. It finished at 0.722 in just under two hours and 128 steps: full category marks on seven of nine hidden regimes, recovery near 0.25 on the two where factor supports co-occur or thin out, and a raw 0.879 cut to 0.722 by the worst-regime factor.

### A failed run

1. **Ace a self-written exam.** One run built a synthetic additive-object problem, recovered all six planted objects at 0.995 mean support correlation and 0.997 reconstruction R², then probed edge cases and correctly rejoined an object its separation stage had split. Every number it produced was excellent, and every number came from data it authored.
2. **Polish the sixteenth decimal.** It measured a 3.3e-16 discrepancy between processing a row alone and in a batch, traced it to BLAS kernel selection, and engineered even that away. Contract exact, determinism bitwise, fit about one second on its own stress case.
3. **Ship on your own evidence.** It closed in thirteen minutes and 56 steps, reporting the system implemented and validated. On the sealed regimes, reconstruction beat its target on all nine suites and factor recovery read zero on five: the learned objects were not the real ones. Raw score 0.234; after the worst-regime factor, exactly 0.

The two runs converged on the same core idea — independent-subspace identification of whitened data. The difference was two hours spent hunting for the regimes that break it versus thirteen minutes spent confirming that it works, and the reward pays for only one of those.

## Failure modes

These are the failure modes we saw across the evaluated runs, and most rollouts exhibit several at once.

| Failure mode | What goes wrong |
| --- | --- |
| A self-authored check read as completion | The run controls both the data and the metric it validates against, so a perfect self-evaluation says nothing about the regimes its simulator never contained. |
| Reconstruction mistaken for recovery | Spreading the data across features reconstructs above target on every suite while recovering none of the underlying factors, and recovery is where the reward lives. |
| The tail zeroes the average | The worst regimes multiply the whole score: one run's raw 0.234 paid out exactly zero. |
| Co-firing factors assumed independent | Regimes where distinct factors habitually co-occur dragged down even the best run, exactly where an independence assumption breaks. |

Every shipped rollout was audited for reward hacking and is clean.
